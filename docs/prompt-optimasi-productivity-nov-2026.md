## 3. Langkah per artikel

1. Baca [Dokumentasi] artikel itu dan artikel live-nya (pakai Chrome kalau WebFetch gagal). Ikuti plan bagian B dan internal link bagian D.
2. Tulis draft lengkap sesuai plan. Fakta yang ada di gerbang verifikasi (bagian C) dan belum dikonfirmasi Harist ditulis dengan kalimat aman tanpa angka yang belum pasti. Draft di [Review] harus bersih, tanpa tanda [PERLU VERIFIKASI]. Daftar yang masih menggantung cukup di bagian C [Dokumentasi] dan kolom Catatan.
3. Kalau ada langkah di dashboard ACCESSTRADE, pakai penanda gambar dan buat MD tugas screenshot sesuai workflow screenshot.
4. Buat Google Docs `[Review] P0xxx <judul singkat>` di SEO Folder (Drive create_file, contentMimeType text/html). Isinya:
   - Header: judul review, ID Pipeline, URL artikel
   - Perlu Keputusan: bernomor, maks 5 poin (H1, meta title, meta description, slug tetap, hal sensitif)
   - Yang Berubah: bernomor, maks 5 poin, satu kalimat per poin
   - Draft Artikel bersih, lengkap dengan meta title, meta description, dan slug
5. Ganti kalimat bagian E di [Dokumentasi] menjadi link ke Docs [Review] (replaceAllText).
6. Pipeline, baca baris terbaru dulu:
   - R Link Draft = link Docs [Review]
   - N Status = Draft Selesai
   - Y Catatan: tambahkan ` | YYYY-MM-DD: Draft [Review] selesai, menunggu verifikasi <item>` di belakang teks lama, jangan timpa
   - Jangan ubah M, O, dan Q
7. Satu baris log di 📚 Referensi & Log, tepat di atas baris "DEFINISI & SUMBER ANGKA". Baca ulang tab log dulu.
8. Laporkan dalam tabel: ID | Docs [Review] | Kata | Perlu keputusan | Masih diverifikasi | Screenshot. Lanjut ke artikel berikutnya kalau Harist bilang lanjut.

Pengajuan ke Indah (status Review, baris baru di tab Review Indah) dilakukan lewat chat update dokumentasi setelah Harist cek draft. Chat ini tidak menulis ke tab Review Indah atau Data Writer.
